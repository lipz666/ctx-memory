# ADR 0004：暂停扩功能，优先补里程碑证据

日期：2026-09-26

状态：实施中

## 背景

M0 尚无真实历史轨迹的 H1 基线；v0.1 尚无真实任务 A/B 成本与成功率、真实负载 G4、双 Agent 任务级接入及连续两周无阻塞事故的证据。虽然 v0.2–v0.4 的部分机制已经写出，不能把功能实现当作版本验收。

## 决定

冻结新的 v0.2–v0.4 能力开发。当前工程工作仅服务于可验证性、数据正确性和已发现的阻塞：真实任务 A/B 采集、响应实际模型名与缓存 token 记账、待审负担、真实并发延迟、Agent 兼容诊断、脱敏轨迹与 H1 标注流程。现有高级功能保留但不宣布通过退出标准。

内部 dogfood 与外部默认值区分：外部默认关闭自动路径；内部启用需有调用预算、失败监控、审核负担统计和可回滚记录。远程 Gate 若在 300 ms 硬超时内无法返回，不能为了积累样本而延长热路径；先记录超时并寻找低延迟路由或本地门控方案。自动漏召回检测排在其余巩固功能之前，但待真实轨迹与标注流程就绪后再实施。

金额只按响应实际模型名及显式配置的该模型价格计算。模型名缺失、价格未知或缓存费率缺失时，金额保持未知，并记录模型名差异；估算的 token 基线不能冒充 A/B 节省额。

## 验收顺序

1. M0：脱敏真实轨迹、标注及 H1 回放基线。
2. v0.1：真实任务 A/B、G1/G4、协议一致性、双 Agent 任务级与连续两周稳定性。
3. 内部 dogfood 产出 Encoder/Gate 与反馈数据；H3 自动漏召回优先于更多巩固能力。
4. 逐项核查 v0.2、v0.3、v0.4 的原定退出标准。任何缺项保持“未通过”。

此顺序用于证据收集；M0 与 v0.1 的实际测试可以并行，但不可用后者的合成样例替代前者的真实轨迹。
