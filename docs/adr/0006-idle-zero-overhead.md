# ADR 0006：空转零开销，上限 3%

日期：2026-09-27

状态：已采纳

## 背景

引擎"无事可做"是常态：记忆库为空、当前作用域没有相关记忆，或者没有达到驱逐阈值的旧工具输出。短任务上，这种状态会占满整个任务。如果每步都付固定开销，短任务就只会变贵。

2026-09-27 对真实 dogfood 任务（OpenClaw，13 步，339,668 输入 token）的逐步归因（`tools/token_attribution.py`）显示：

| 组成 | 占全部输入 |
| --- | --- |
| OpenClaw 自身系统提示 | 33.1% |
| OpenClaw 自身工具 schema | 52.9% |
| 对话历史 | 13.1% |
| ctx 追加（L0 说明、记忆） | 0% |
| ctx MCP 工具 schema | 0%（OpenClaw 路径未注册 MCP） |
| 按默认策略可驱逐的旧工具输出 | 5.1%（从未达到 20,000 token 批量阈值） |

在 Claude Code/Codex 路径上，MCP 工具会随每次请求发送。原先 6 个工具约 337 token/步，约为 22k 固定前缀的 1.5%。

## 决定

1. **空转时请求必须逐字节一致。** 没有命中记忆、也没有驱逐时，代理把 Agent 的原始字节原样转发，包括键顺序、空白和转义；不追加 L0 说明，也不重新序列化。`tests/idle_overhead_smoke.py` 做回归保护。
2. **MCP 默认只列出 `recall` 和 `expand`**（`mcp_tools: minimal`，约 106 token/步）。其余工具仍可按名称调用；需要时可设 `mcp_tools: full`。
3. **硬指标：短任务上的空转开销 ≤ 3%**，按"ctx 发出请求的每步输入 / Agent 原始请求的每步输入 − 1"计算。它包括 MCP schema，但不包括模型轨迹差异；后者按 ADR 0005 通过同层计量的步数和每步输入分开报告。
4. 常驻规则（`kind: rule` 或 pinned）属于用户主动配置的注入，不计入空转；它们会在任务成本中如实体现。

## 后果

当前 OpenClaw 路径空转开销实测为 0；Claude Code/Codex 路径约 0.5%。本 ADR 同时说明，这条路径上的 v0.1 节省空间有上限：每步 86% 的输入是 Agent 自身前缀，ctx 不改写这部分，而且其中大部分已经命中缓存。可能的收益只能来自历史和大块工具输出。同日的长会话 A/B（[记录](../ab-metered-2026-09-27.md)）显示：驱逐让每步输入减少 25%，但也让前缀缓存失效，成本大致持平。
