# ADR 0005：G2 按每成功任务成本衡量，而非原始输入 token

日期：2026-09-27

状态：已采纳

## 背景

2026-09-27 的 OpenClaw A/B 报告"ctx 输入 token 高 21.6%"。事后归因发现：

- 两臂的计量来源不同。ctx 臂由代理逐步记账；直连臂只有 OpenClaw 汇总，没有步数、没有逐步缓存数据。
- 有逐步记录的 ctx 臂修改请求 0 次、驱逐 0 次（重复配对明确记录）；隔离实例没有记忆，也没有注册 MCP。发往网关的请求与 Agent 原始请求逐字节一致。
- 把两臂都接入同一只读计量层后，clamp 回归一对的每步输入几乎相同（24,955 与 24,824 token），总量差来自步数（14 与 16 步）。

因此，原始输入 token 之差主要反映模型轨迹长度的随机性，不是引擎开销。更重要的是，输入 token 的价格并不一致：缓存读取通常远低于未缓存输入。

## 决定

1. G2 的主指标是**每成功任务成本**：`(未缓存输入 × 输入单价 + 缓存输入 × 缓存单价 + 输出 × 输出单价 + 引擎自身 LLM 调用费用) / 成功任务数`。失败任务的花费计入分子，不从样本中剔除。
2. 价格未核实时，报告以上四项 token，金额保持未知，不用原始输入 token 之差替代。
3. A/B 的两臂必须由**同一计量层**记账：直连臂接入 `--meter-only` agent，请求逐字节转发、不编译，只记录用量（`tests/openclaw_ab.py` 默认这样运行）。
4. 同时报告步数与每步输入。每步输入相同而步数不同时，不能把差额归因于 ctx。
5. 对外表述以实测为准。当前证据只支持"空转时不增加每步成本"和"长会话中减少原始输入 token"。长会话 A/B 中，原始 token −25% 折算成本后大致持平（缓存失效），因此不能对外宣称省钱。

## 后果

旧的 A/B 数据（2026-09-27 之前）直连臂没有逐步数据，只能作为流程试跑。今后判定 v0.1 退出标准时，只采用两臂同层计量的配对结果。
