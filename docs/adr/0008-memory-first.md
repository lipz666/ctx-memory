# ADR 0008：以长期记忆为目标，精简引擎

日期：2026-09-28

状态：已采纳；取代 ADR 0004 的验收顺序，以及 ADR 0005–0007 中把成本当作目标的部分

## 背景

项目的目标是一个好用、拥有长期记忆的上下文引擎。此前的工作逐渐偏向“是否省钱”：成本计量、A/B、Gate 延迟与驱逐。架构审视发现，两条主干反而不合格：

- **写入几乎不产出。** 生产实例真实使用多日后记忆为 0 条。Encoder 只在少数关键词或事件时启动，且只看到事件特征片段，看不到对话本身。
- **召回质量差。** 查询只按空格切词，中文整句和长句失效；在 90 条自然提问上，正确记忆进入前 3 的比例为 31%。
- **作用域失效。** MCP 召回固定不带项目；代理只有收到请求头才知道项目。

与此同时，Gate、分类器、ActionGuard 三套机制都在决定“要不要召回”，本质上是在给弱检索打补丁；成本与驱逐体系与目标无关。

## 决定

1. 核心只保留记忆的写入、存储、召回与注入。验收看召回质量（评测集）与端到端的记忆生命周期，不再以 token 或金额为指标。
2. 写入改为会话结束提炼：读完整的脱敏对话，产出创建或更新，近似去重；规则永不自动生效。
3. 召回改为单一入口的混合检索：本地语义模型 + 中文分词 BM25 覆盖度，阈值在评测集的一半上调定、另一半验证。
4. 项目自动识别；召回结果按会话锚定并持续可见。
5. Gate、分类器、ActionGuard、驱逐移入 `experimental/`，默认关闭；成本与价格代码删除。不因“长期未用”归档记忆。
6. 记忆格式精简到 v2，旧文件自动迁移；存储合并为一个 SQLite，事件只存增量。

## 后果

- 召回（前 3 命中）从 31% 提升到 93%，误召回保持 0（见 [验收记录](../memory-engine-acceptance.md)）。
- 首次使用需下载约 330 MB 语义模型；二进制因 ONNX Runtime 增大。下载失败时退回关键词检索（前 3 命中 51%）。
- 提炼依赖外部模型的质量与可用性；它在后台运行，不阻塞 Agent。
- 旧的 A/B、Gate 延迟、dogfood 证据文档保留为历史记录，不再作为里程碑门槛。
