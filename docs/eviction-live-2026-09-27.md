# 冻结长工具历史的真实网关驱逐实验

日期：2026-09-27。用 `tests/eviction_live_pair.py` 构造一条含 130,000 字符旧 CI 日志的合法工具回合，后接多轮短对话，再把**完全相同的请求**分别发给网关直连和隔离 ctx。请求模型相同，响应实际模型均为 `gemini-3.8-flash`。最终问题要求只答 `OK`。

第二次独立运行：直连输入 44,124、输出 1 token；ctx 输入 215、输出 1 token。两臂都回答 `OK`；ctx 确认修改请求并批量驱逐 1 条旧工具结果。输入 token 减少约 **99.5%**。第一次运行的输入为 44,124 对 209 token，也驱逐 1 条，输出均为 1 token。

这证明默认阈值下的**驱逐机制在长工具历史里确实省 token**。它是冻结请求的仿真协议实验，不能代替 Agent 任务级成功率或每成功任务成本。三项仿真编码任务 A/B 中未观察到可归因的节省；支付对账重复配对的 28 个 ctx 步骤修改/驱逐均为零。当前 v0.1 的商业主张只在某些长上下文工作负载中有机制证据，真实工作分布与总体收益仍未证明。
