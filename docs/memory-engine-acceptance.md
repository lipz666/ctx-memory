## 召回评测

`tests/recall_eval.py`：32 条记忆分属 3 个项目和全局，90 条提问覆盖中文改写、英文改写、跨语言、长对话、报错原文、精确关键词，以及 19 条不应命中的问题（无关问题和其他项目的问题）。阈值只在 dev 半集上调定（`min_similarity` 0.30 → 0.34，`min_keyword_fallback` 0.30），test 半集单独验证。数据：[新引擎](recall-eval-2026-09-28.json)、[重构前](recall-eval-baseline-2026-09-27.json)。

| 类别 | 重构前 | 新引擎 |
| --- | --- | --- |
| 精确关键词 | 8/8 | 8/8 |
| 中文改写 | 4/18 | 18/18 |
| 英文改写 | 3/8 | 8/8 |
| 跨语言 | 4/26 | 24/26 |
| 报错原文 | 3/6 | 6/6 |
| 长对话 | 0/5 | 2/5 |
| 误召回（19 条） | 0 | 0 |
| **前 3 命中 / 首位命中** | **31% / 30%** | **93% / 90%** |

test 半集单独：前 3 命中 92%，误召回 0。没有语义模型时（关键词兜底）前 3 命中 51%。

**已知弱点：** 话题混杂的长对话式提问（例如“我刚重构了 ledger，想合到 main 再上线，帮我确认上线前的步骤”）会被其中的“ledger”“main”等词带偏，5 条中错 3 条。

## 延迟

`tests/recall_latency.py`：1,000 条中英文记忆，10 个项目，新会话中的新用户消息，经由模拟上游。

| 指标 | 结果 |
| --- | --- |
| 首次为 1,000 条记忆生成向量 | 39 s（一次性；按文本哈希缓存） |
| 守护进程启动到可用（向量已缓存） | 0.6 s |
| 代理热路径 P50 / P95 / 最大 | 39 / 43 / 120 ms |

## 真实网关 + 真实 Agent

`tests/extraction_live.py`，网关模型 `gemini-3.8-flash-high`，隔离实例，Agent 为 OpenClaw。数据：[JSON](extraction-live-2026-09-28.json)。

1. **第一轮（设计有缺陷）。** 任务是修复 billing 测试，用户消息附带“以后回答我请用中文”。任务完成且独立验证通过，项目识别为 `billing`，提炼 24 s 完成，正确保存了中文偏好。但没有保存舍入规则：这些规则本来就写在仓库 README 里，提炼提示要求不记“读代码就能知道的”内容。新会话的正确回答来自读 README，注入 0 条。这说明提炼器克制是对的，但场景无法证明学习效果。
2. **第二轮。** 用户消息里加入仓库中没有的知识：“修好的代码要合到 release/2026-q4，合并前找 @wang-li 审核”。
   - 任务：OpenClaw 25 步完成并通过验证；
   - 提炼：87 s 完成，生成 2 条记忆（全局“使用中文回答”，`billing` 项目“合并分支与审核要求”），0 条跳过；
   - 新会话（同名项目的新副本）问“修完应该合到哪个分支、找谁审核”：注入 1 条记忆，回答“代码应该合并到 `release/2026-q4` 分支，合并前必须找 @wang-li 进行代码审核”，并使用中文。

两轮均只调用 1 次引擎模型。
