## v0.1 真实任务 A/B

使用 [OpenClaw 配对实验脚本](../tests/openclaw_ab.py) 对每个任务复制两份相同的仓库起点，随机交换直连与 ctx 的先后次序。每臂一个新 Agent 会话，用相同模型、提示和任务验证命令。ctx 臂只运行代理、Observer、编译与驱逐；Encoder、Gate、巩固及 recheck 关闭。脚本输出每臂成功与否、时长和 Agent 报告的 token；ctx 臂还记录响应实际模型与缓存 token。需要至少两个 Agent 的任务级接入，Hermes 当前是单独阻塞项。

任务清单 JSON 示例：

```json
{
  "tasks": [
    {
      "id": "fix-regression-001",
      "source_dir": "/absolute/path/to/a/clean/fixture",
      "prompt": "修复指定的失败测试，并运行验证命令。",
      "verify": ["python3", "-m", "unittest", "discover"],
      "timeout_seconds": 180
    }
  ]
}
```

运行前将 `CTX_TEST_LIVE_BASE_URL`、`CTX_TEST_LIVE_MODEL`、`CTX_TEST_LIVE_CREDENTIAL_REF` 设为所用网关、模型和 Keychain/env 凭证引用，执行 `cargo build --release && python3 tests/openclaw_ab.py tasks.json --output result.json`。脚本在临时目录复制任务，不编辑源目录；不输出密钥。用户已允许用设计上贴近真实工作的仿真任务；库存批量预留、支付对账、回归修复三个任务的独立验证器已建立。仿真 A/B 结果与正式内部任务成功率分别报告。

**成本口径：** A/B 需分别汇总成功任务的实际输入、输出、缓存读取/写入 token 及重试调用，按**响应中的实际模型名**和经核实价格计费，再加 Encoder/Gate/recheck 等引擎调用费用。请求模型名不等于响应模型名时记告警。当前的面板“基线成本”只由请求长度估算，不是 A/B 对照；不能代替任务级真实成本。网关尚未提供已核实的 `gemini-3.8-flash` 定价；直连臂的 OpenClaw 汇总只报告请求模型名，正式成本还需要网关侧原始用量/模型记录或共同的只读计量层。

成功率比较使用同一任务的成对结果；成本比较只对两臂都成功的任务给出配对差额，并另列每臂“每成功任务总成本”（包括失败任务消耗，避免只挑成功样本）。缓存命中率为缓存读取输入 token / 全部输入 token。G4 用代理响应头 `X-Ctx-Hot-Path-Ms` 记录实际发往上游前的耗时，在真实网关、并发负载下分开报告 P50/P95、样本数和失败数；端到端时长只作用户体验指标。

## 内部 dogfood 与 M0

外部默认仍关闭自动路径。内部试用已开启 Encoder 与 Gate，设置每日引擎调用上限 20，ActionGuard 保持 advisory；每日聚合快照从 2026-09-27 至 2026-10-10 运行。2026-09-27 通过独立入口完成一项**真实仓库维护任务**：OpenClaw 正常退出、独立验证通过、记录 1 个 success Hook、13 个代理步骤、339,668 输入和 1,337 输出 token；Encoder 处理了 1 次模型调用，无失败。此项只算一天的一条工作样本，尚不能形成连续两周或 Gate 效用标签。真实任务需要项目、会话标识及任务成败 Hook；隔离真实网关烟测已验证独立入口会把代理步骤关联到同一会话。当前网关普通响应约数秒，远超 Gate 的 300 ms 超时；Gate 虽已按本次试用要求开启，但若有记忆和决策点，远程门控预期超时并降级，不能将此类超时当作有效效用标签。需验证低延迟路由或本地方案，监控降级次数并保持 Agent 透传。

本机日常 OpenClaw 默认仍指向另一模型。为避免改变其日常模型，新增[独立试用入口](../tools/openclaw_dogfood.py)：`python3 tools/openclaw_dogfood.py --workspace /path/to/work --message '任务' --verify-command 'python3 -m unittest discover'`。它使用持久的独立 OpenClaw profile 走生产 ctx，提交任务起止 Hook；只有提供独立验证命令才记 success/failure，未验证记 unknown。隔离烟测和一项真实仓库任务已证实入口可用；持续两周仍需团队实际采用。

M0 需要**脱敏的真实 Agent 轨迹**与“此时需要哪些记忆”的标注：先由 LLM 依据失败和纠正回溯初标，再抽 10% 人工复核；分别报告触发器命中率、精确率、漏召回与标注一致性。轨迹仅在本机采集和评测，任何跨人共享或外发前需完成蓝图 14.2 节的数据使用与脱敏流程。已起草[内部轨迹数据使用流程](internal-trace-data-process.md)，仍需组织负责人批准；虚拟样本不能填补这项证据。

**H1 决策：暂不裁决。** 仿真样本按三条记忆编写，7/7 触发命中有明显选择偏差。只有真实轨迹经授权、完成初标与人工复核后，才比较基线并决定是否执行蓝图风险表中的“仅保留错误签名/工具触发、增加情境召回权重”退路。自动漏召回检测（H3）排在该决策之后、其余巩固功能之前；在此之前不以仿真数据宣称 H3 趋势。
