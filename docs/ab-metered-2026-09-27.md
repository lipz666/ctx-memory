# 同层计量 A/B 与 +21.6% 归因（2026-09-27 下午）

回应上午 [A/B](ab-2026-09-27.md) 中"ctx 输入 token 高 21.6%"。本轮起，两臂都经过同一 ctx 计量层：直连臂使用 `--meter-only` agent，逐字节转发、不编译（[ADR 0005](adr/0005-g2-cost-per-successful-task.md)）。模型请求 `gemini-3.8-flash-high`，响应报告 `gemini-3.8-flash`。ctx 臂只运行 v0.1 代理/编译/驱逐，Encoder、Gate、巩固均关闭，记忆库为空。数据：[短任务](openclaw-ab-metered-short-2026-09-27.json)、[长会话](openclaw-ab-metered-long-2026-09-27.json)、[汇总](openclaw-ab-metered-summary-2026-09-27.json)。

## 一、+21.6% 的来源：轨迹步数，不是引擎开销

| 证据 | 结果 |
| --- | --- |
| 上午 ctx 臂对请求做了什么 | 空记忆库、未注册 MCP；重复配对记录修改 0 次、驱逐 0 次。发往网关的字节与 Agent 原始请求一致。 |
| 上午两臂的计量方式 | 不同。ctx 臂逐步记账；直连臂只有 OpenClaw 汇总，没有步数。 |
| 真实 dogfood 任务逐步归因（13 步，[数据](dogfood-attribution-2026-09-27.json)） | OpenClaw 系统提示 33.1%、OpenClaw 工具 schema 52.9%、历史 13.1%；ctx 追加 0%，ctx MCP 0%；可驱逐旧工具输出 5.1%，从未达到阈值。 |
| 本轮短任务 3 对（都成功） | ctx 修改 0 次。每步输入比 0.951 / 0.987 / 0.972，总输入比 0.646 / 0.880 / 0.918；差异全部来自步数：19 对 28、33 对 37、17 对 18。 |

同一个"什么都没做"的代理，上午"贵 21.6%"，下午"便宜约 12%"。短任务上的总量差是模型轨迹的随机波动，不能归因于 ctx，两个方向都不能。空转开销实测为 0（[ADR 0006](adr/0006-idle-zero-overhead.md)）。

## 二、长会话任务：驱逐生效，但省下的主要是本来就便宜的缓存 token

任务 `billing-noisy-ci`：修复 3 个独立缺陷；每次运行测试输出约 140–160 KB DEBUG 日志；重复 3 次，每次随机交换两臂顺序。

| 指标（3 次合计） | ctx | 直连 | ctx / 直连 |
| --- | --- | --- | --- |
| 成功 | 3/3 | 3/3 | — |
| 步数 | 124 | 110 | 1.13 |
| 每步输入 token | 60,909 | 80,983 | **0.75** |
| 缓存命中率 | 75.0% | 81.1% | — |
| 未缓存输入 | 1,892,004 | 1,687,704 | **1.12** |
| 缓存输入 | 5,660,699 | 7,220,378 | 0.78 |
| 输出 | 9,635 | 9,492 | 1.02 |
| 修改请求 / 驱逐工具结果 | 75 / 189 | 0 / 0 | — |

逐对结果：总输入比 0.60 / 1.11 / 0.90，每步输入比 0.78 / 0.63 / 0.82，未缓存输入比 0.82 / **2.05** / 0.95。

**解释。** 驱逐会改写历史中段的旧工具输出，从被改写处起，网关的前缀缓存全部失效，此后要以未缓存价格重新读入。直连臂的旧日志虽然很大，却一直命中缓存。因此原始 token 少了约 25%，未缓存 token 反而多了约 12%。

**折算成本。** 网关单价未核实，以下只是示意。每成功任务的"等效未缓存 token"（输出按输入的 4 倍计）：缓存单价为输入的 10% 时，ctx 约比直连 **+2.0%**；为 25% 时约 **−5.2%**。也就是说，在当前驱逐策略下，长会话任务的每成功任务成本大致持平，远未达到 G2 的 −20%。

**成功率。** 驱逐后成功率没有下降（3/3 对 3/3），但样本只有 3 对，只能说明"没有观察到损害"。

## 三、结论与下一步

1. v0.1 的主张应改为可检验的形式："空转不增加每步成本；长会话中减少原始输入 token"。"每成功任务成本下降"**目前不成立**，因为当前驱逐策略与前缀缓存冲突。
2. 下一项工作是回应这条证据，不属于新功能：**缓存感知的驱逐**。只有当预计节省超过缓存重建成本时才驱逐，例如把阈值与"被改写位置之后的已缓存 token × (1 − 缓存价比)"比较；或者减少批次数、一次驱逐更多。改动后用同一长会话任务重做 ≥5 对，并按 ADR 0005 以成本口径判定。
3. 需要网关提供经核实的 `gemini-3.8-flash` 输入、缓存读取和输出单价。否则 G2 只能停在 token 层面。
4. 本轮 3 + 3 对样本仍然太小，只用于纠正方向，不作为 v0.1 退出判定。
