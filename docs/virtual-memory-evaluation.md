# 虚拟记忆端到端评测

日期：2026-09-26。运行命令：`cargo build && python3 tests/virtual_memory_journey.py`。

脚本用临时 `CTX_HOME`、本地回显模型和临时端口创建 13 条虚拟记忆，不读取或修改用户的 `~/.ctx`。记忆覆盖 payments / atlas 两个项目、过期状态、归档事实、待审行动前教训、重复情节和三条有独立任务事件证据的教训。9 个标注步骤包括目标召回、跨项目隔离、过期与归档排除、无关问题弃权、行动前召回及错误签名修复。

| 指标或行为 | 结果 |
| --- | --- |
| 9 步离线回放的目标记忆召回率 | 5 / 5 = 100% |
| 注入精确率 | 5 / 5 = 100% |
| 触发器命中率 | 3 / 5 = 60%；行动前通道单独计数 |
| 待审隔离 | 行动前教训在批准前未召回；批准后可在 pre_action 命中 |
| 漏召回修复 | 显式上报一次错误后，生成并命中 `origin=repair` 的错误签名触发器 |
| 巩固 | 5 次正向反馈、3 个会话后将一条 lesson 升为 pinned；重复情节取代；三条独立证据生成待审 skill |
| 回滚 | 整批恢复原 tier 与状态，并删除该批次新建的 skill |

第一轮回放曾得到 5 / 5 目标召回、5 / 7 注入精确率（71.4%）。两个误召回来自双词查询只共享一个普通词。将多词词面召回的最低匹配数收紧到两个**不同词**后，精确率变为 5 / 5，目标召回保持 5 / 5。场景连续复测三次结果一致；`cargo clippy --all-targets -- -D warnings`、19 个 Rust 单元测试及全部冒烟测试通过。最新 100 次串行本地模拟上游的代理额外延迟 P95 为 0.71 ms。

## 真实网关的虚拟事件

`tests/gateway_encoder_live.py` 在另一临时 `CTX_HOME` 中，使用配置好的模型凭证引用上报一条虚拟用户纠正。第一次运行发现网关模型将 JSON 包在 Markdown 围栏中；第二次发现触发器用了未定义事件名和数字优先级。修复围栏解析、补全合法字段枚举与重试提示后，两次复测均将任务处理为 `done`，生成 1 条 `pending_review` 记忆。审核通过后，以 `deploy payments-demo` 回放，目标记忆被召回；最近一次生成了 2 条触发器。这个测试只发送虚构内容，不向用户的生产记忆库写入数据。

此测试需要外部网关，会消耗模型调用，并非离线回归的必跑项。运行方式：

```bash
CTX_TEST_LIVE_BASE_URL=https://YOUR-GATEWAY/v1 \
CTX_TEST_LIVE_MODEL=YOUR-MODEL \
CTX_TEST_LIVE_CREDENTIAL_REF=keychain:YOUR-SERVICE \
python3 tests/gateway_encoder_live.py
```

这些数字只说明此人工构造场景的行为，不能外推为真实任务精确率，也不满足蓝图 H1、H2、H3、G5 的退出标准。下一阶段仍需要脱敏历史轨迹、人工标注与长期在线对照。词面检索对中文分词、改写表达和同义词仍有局限；本次改动选择更保守的召回以降低上下文污染。
