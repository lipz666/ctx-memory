# 内部 Agent 轨迹数据使用流程草案

状态：**待组织负责人批准，尚未生效**。日期：2026-09-27。

此草案用于蓝图 14.2 节和 M0/H1。当前 A/B 使用隔离目录中的仿真代码任务；它们不构成内部真实轨迹许可，也不能替代 M0 的真实样本。

## 使用范围与责任

1. 项目负责人指定一个数据负责人，列出参与试用的 Agent、项目、成员与保留期限。未列入的工作不进入 M0 数据集。
2. 参与成员在试用前知悉：本机引擎会记录模型请求、工具结果、召回决策和任务结果，用于触发器评测、故障复盘及成本分析。成员可以将项目或会话排除，排除后不导出该轨迹。
3. 数据负责人批准**本机内**的轨迹筛选、脱敏和标注范围。跨成员共享、上传外部标注服务或向模型发送轨迹摘要，各自需要单独记录批准与服务边界。
4. 不收集凭证、令牌、环境文件、用户个人消息正文或未授权的第三方数据。若这些内容出现在记录中，先在本机隔离并删除，不能以“后续再脱敏”为由外发。

## M0 操作步骤

1. 从同意范围内选择任务序列，保留项目与会话的随机别名、事件相对顺序、错误签名、脱敏的工具/用户事件、当时可用记忆 ID、任务成败；不导出原始授权头或完整配置。
2. 两次检查脱敏：事件入库时一次；制作评测包时再一次。抽样人工检查脱敏效果，通过后才交给标注者或获批准的模型服务。
3. LLM 初标每个失败和纠正前的“需要记忆时刻”及对应记忆；同时记录模型、提示版本、输出和无法判定项。随机抽取至少 10% 由懂任务的人复核，记录一致率、分歧和最终裁决。
4. 将裁决后的轨迹与记忆快照放入隔离的评测目录；运行 `ctx eval replay`，报告触发器命中率、注入精确率、弃权率、每步 token 和检索 P95。保留样本数、项目分布及置信区间；仿真轨迹单独报告。
5. 数据负责人按约定期限删除原始导出与临时标注文件；聚合指标与匿名化的评测方法可继续保留。成员要求排除自己的轨迹时，从评测集及衍生标签中删除并重跑统计。
